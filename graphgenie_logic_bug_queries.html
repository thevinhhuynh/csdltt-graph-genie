Tài liệu tổng hợp truy vấn gốc Q, truy vấn biến đổi Q′, quan hệ kết quả kỳ vọng và sai lệch lịch sử được trình bày trong bài báo GraphGenie.

1. Đếm quan hệ không chính xác

Nhóm này gồm hai trường hợp RedisGraph trả về số đếm khác nhau cho các truy vấn phải tương đương.

1.1. Đếm quan hệ trực tiếp và qua định danh

RedisGraph CountIdProperty Issue #2744

Truy vấn gốc Q

MATCH ()-[a]-()
RETURN count((a));

Truy vấn biến đổi Q′

MATCH ()-[a]-()
RETURN count(id(a));

Quan hệ kỳ vọng: Result(Q) = Result(Q′)

Kết quả lịch sử: 20.000 ≠ 39.993

Hai biểu thức cùng đếm tập quan hệ được gán cho biến a. Theo phản hồi nhà phát triển được bài báo dẫn lại, RedisGraph bỏ sót quan hệ khi biến quan hệ không được tham chiếu ở nơi khác trong truy vấn.

Nguồn: RedisGraph #2744 · script tái hiện trong repository.

1.2. Đảo thứ tự đường đi đối xứng

RedisGraph SymmetricPattern Issue #2865

Truy vấn gốc Q

MATCH (a:A)-[*1..2]-(b:B)
RETURN count(1);

Truy vấn biến đổi Q′

MATCH (b:B)-[*1..2]-(a:A)
RETURN count(1);

Quan hệ kỳ vọng: Result(Q) = Result(Q′)

Kết quả lịch sử: 204 ≠ 238

Cạnh không có mũi tên nên việc viết đường đi từ A đến B hoặc theo thứ tự ngược lại phải biểu diễn cùng tập đường đi. Bài báo xác định nguyên nhân ở logic dừng mở rộng đường đi không chính xác khi phát hiện chu trình.

Biến thể trong script tái hiện của repository:

Q trong artifact

MATCH (s1:B)-[*1..2]-(s3:A)
RETURN count(s1);

Q′ trong artifact

MATCH (s3:A)-[*1..2]-(s1:B)
RETURN count(s1);

Nguồn: RedisGraph #2865 · script tái hiện trong repository.

2. Lỗi toán tử thực thi Expand(Into)

Neo4j 5.1.0 MoveLabelPredicate Issue #12991 Recommendations

Q — kiểu quan hệ nằm trong mẫu

OPTIONAL MATCH
  (s1)-[s0:DIRECTED]-()<-[s2:ACTED_IN]-(s1)
RETURN count(s1);

Q′ — kiểu quan hệ chuyển sang WHERE

OPTIONAL MATCH
  (s1)-[s0]-()<-[s2:ACTED_IN]-(s1)
WHERE s0:DIRECTED
RETURN count(s1);

Quan hệ kỳ vọng: Result(Q) = Result(Q′)

Kết quả trên Neo4j 5.1.0: 43 ≠ 491

Sau khi sửa: hai truy vấn cùng trả về 491.

Cả hai truy vấn cùng yêu cầu s0 có kiểu DIRECTED, s2 có kiểu ACTED_IN và hai đầu ngoài là cùng nút s1. Việc đổi vị trí biểu diễn điều kiện kiểu quan hệ không được làm thay đổi số lần khớp.

Bài báo liên hệ sai lệch với toán tử kế hoạch thực thi Expand(Into), khiến Neo4j bỏ sót đường đi thỏa mãn điều kiện.

Nguồn: Neo4j #12991 · script tái hiện trong repository.

3. Lỗi phân tích biểu thức độ dài biến đổi

AgensGraph PatternPartition Issue #609

Truy vấn gốc Q

MATCH (a)-[*1..1]->(b)
RETURN count(a);

Truy vấn biến đổi Q′

MATCH (a), (a)-[*1..1]->(b)
RETURN count(a);

Quan hệ kỳ vọng: Result(Q) = Result(Q′)

Kết quả lịch sử: Q trả về 100, còn Q′ báo column "a" does not exist.

Phép PatternPartition tách mẫu nhưng không bổ sung ràng buộc dữ liệu mới. Tuy nhiên, khi xử lý biểu thức độ dài biến đổi [*1..1], AgensGraph làm biến a không còn hiển thị đối với hàm tổng hợp.

Nguồn: AgensGraph #609.

5. Lưu ý khi tái hiện

Các con số trên là kết quả lịch sử. Chúng chỉ tái hiện khi sử dụng đúng phiên bản DBMS, đúng dataset và đúng cấu hình liên quan. Trên phiên bản đã sửa, Q và Q′ phải cho cùng kết quả hoặc cùng thực thi thành công.

  • Ghi lại phiên bản DBMS trước khi chạy.
  • Dùng đúng dữ liệu hoặc script tạo dữ liệu của issue.
  • Không thay đổi hướng cạnh, tên nhãn, OPTIONAL MATCH, WHERE hoặc hàm count.
  • Chạy Q và Q′ trên cùng trạng thái dữ liệu, không cập nhật dữ liệu ở giữa.
  • Phân biệt “không tái hiện trên bản mới” với “lỗi chưa từng tồn tại”. Một ca đã sửa trở thành kiểm thử hồi quy.
